How this works

nixgen writes new files. The ones you already have are read at most, never changed. The tabs are the order of work: Setup, then Options, then Packages — then check it and take it.

  1. Start in Setup. The host name, the user account, the channel and the boot loader. It writes the two files a fresh install still needs: configuration.nix, the half you write by hand, and flake.nix, the way in to the whole system. Already have a configuration.nix? Press Import configuration.nix first — your settings come back as fields you can edit, and the ones on this tab (the host name, the user, the boot loader) are filled in from your file — then carry on here. 
    /etc/nixos/
|-- flake.nix                   from Setup
|-- configuration.nix           from Setup
|-- hardware-configuration.nix  written when you installed; left alone
`-- generated.nix               what you build here
    flake.nix reads configuration.nix, which reads the other two.
  2. Then Options — the settings. Type what you are after — ssh, firewall, timeZone — and click a result to bring it here. The four dropdowns above the results do a kernel, a desktop, a graphics driver or a language in one go.
  3. Then Packages — the software. Search, or pick a category under Common apps. Everything you click goes into environment.systemPackages.
  4. Press Check syntax when you are done. It runs the real Nix parser and says where the file breaks. It cannot tell you whether a value is the right type — that is the next step's job. Fix anything it reports before going on.
  5. Press Download all three. One archive holding all three files. Unpack it beside the hardware-configuration.nix you already have, then run sudo nixos-rebuild dry-build, and switch only if that is clean. Setup prints the command.

Closing the tab loses the form. Nothing is kept between visits, so the file is the save: download generated.nix, and Import configuration.nix brings those settings back as they were. The Setup fields come back only from a file that sets them — a configuration.nix does, a generated.nix usually does not.

You can go back to a tab at any time — the order above is where to start, not a door that shuts behind you. The longer version.

使い方

nixgen は新しいファイルを作ります。今あるファイルは読むだけで、書き換えることはありません。タブの並びが、そのまま進める順序です。Setup → Options → Packages、そして確認して受け取ります。

  1. まず Setup から。ホスト名、ユーザー、チャンネル、ブートローダーを決めます。インストール直後に足りない2つのファイルは、ここで用意されます。手で書く側の configuration.nix と、システム全体の入口になる flake.nix です。すでに configuration.nix がある場合は、先に Import configuration.nix を押してください。今の設定が編集できる入力欄として戻り、このタブの項目(ホスト名・ユーザー・ブートローダーなど)も読み込んだファイルから埋まります。そのままここから続けてください。 
    /etc/nixos/
|-- flake.nix                   Setup から
|-- configuration.nix           Setup から
|-- hardware-configuration.nix  インストール時に作られたもの。触りません
`-- generated.nix               ここで作るファイル
    flake.nix が configuration.nix を読み、そこから残りの2つを読みます。
  2. 次に Options — 設定項目です。探しているものを入力します — ssh、firewall、timeZone など。結果をクリックすると、ここに入ります。結果の上にある4つのプルダウンでは、カーネル・デスクトップ・グラフィックス・言語がひと通り揃います。
  3. 次に Packages — ソフトウェアです。検索するか、Common apps の分野から選びます。クリックしたものは environment.systemPackages に入ります。
  4. ひと通り終えたら Check syntax を押します。本物の Nix のパーサーを通し、どこで壊れているかを伝えます。値の型が正しいかどうかまでは分かりません。それは次の手順の役目です。ここで指摘が出たら、直してから先に進んでください。
  5. Download all three を押します。3つのファイルが1つの書庫で出てきます。既にある hardware-configuration.nix の隣に展開し、sudo nixos-rebuild dry-build を実行してください。問題が無いときだけ切り替えます。コマンドは Setup に表示されています。

タブを閉じると、入力した内容は消えます。何も保存していないので、保存にあたるのはファイルです。generated.nix をダウンロードしておけば、Import configuration.nix で元のとおりに戻せます。Setup の入力欄が戻るのは、その値を書いてあるファイルを読んだときだけです。configuration.nix には書いてありますが、generated.nix にはたいてい書いてありません。

タブはいつでも戻れます。上の順序はどこから始めるかの話で、一度離れたら戻れないわけではありません。詳しい説明。

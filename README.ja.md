# nixgen

NixOSの設定を、検索とフォームで作れるようにする道具です。設定項目24,517個とソフトウェア144,200個の中から探して、チェックボックスや入力欄で値を決めると、そのまま使える設定ファイルが出てきます。

![nixgen](docs/screenshot.png)

English: [README.md](./README.md) ·
ホームページ: <https://hatake716.github.io/nixgen/>

> **ベータ版です。** 作者の自宅マシンと仮想マシンでは動いていますが、それ以外の環境で何が起きるかは分かっていません。適用する前に、後述の `dry-build` で必ず確認してください。

---

## この道具は何をするのか

NixOSでは、システムの設定を1つのファイルに書きます。SSHを有効にしたいなら、こう書きます。

```nix
services.openssh.enable = true;
```

問題は、**この「項目の名前」を覚えていないと何も書けない**ことです。項目は全部で24,517個あります。公式ドキュメントは英語で、目的の項目にたどり着くまでに時間がかかります。

nixgenは、この部分を肩代わりします。

1. 検索欄に `ssh` と入力する
2. 出てきた `services.openssh.enable` をクリックする
3. スイッチをONにする
4. 右側に `services.openssh.enable = true;` と書かれたファイルが出来上がる

項目名を覚えていなくても、思いついた単語で探せば見つかります。

### 誰に向いているか

- **設定項目の名前を覚えていられない人。** 使う頻度が低い設定ほど、毎回ドキュメントを探すことになります
- **NixOSを始めたばかりの人。** 「そもそも何を設定できるのか」が分からない段階では、検索欄に単語を入れて眺めるだけでも地図の代わりになります
- **バージョンを上げた直後の人。** 手元の設定ファイルを読み込ませると、**なくなった項目に色が付いて出てきます**

### 向いていないか

- **項目名をだいたい覚えていて、テキストエディタで直接書いたほうが速い人。** この道具は遠回りにしかなりません
- **NixOS以外のLinuxを使っている人。** 残念ながら、この道具はNixOS専用です

## インストール

必要なのはNixOS、または他のLinux上のNixだけです。**ファイルをダウンロードする必要はありません。**

### ステップ1 — flakesを有効にする

「flakes」はNixの新しい書き方です。この道具はそれを使うので、先に有効にしておく必要があります。NixOSを新規インストールした直後は無効になっています。

まず、有効かどうかを確認します。

```bash
nix flake --help
```

**ヘルプがずらっと表示されたら、すでに有効です。** ステップ2へ進んでください。

「実験的機能です」というエラーが出た場合は、設定ファイル(`/etc/nixos/configuration.nix`)を開いて、`{` と `}` の間に次の1行を足します。

```nix
nix.settings.experimental-features = [ "nix-command" "flakes" ];
```

保存したら、システムに反映させます。

```bash
sudo nixos-rebuild switch
```

もう一度 `nix flake --help` を実行して、ヘルプが出れば成功です。

### ステップ2 — 起動する

```bash
nix run github:hatake716/nixgen
```

**これだけです。** ダウンロードもインストール作業も要りません。Nixが必要なものを勝手に集めて起動します。

**初回は5分ほどかかります。** 内部では次のことをしています。

1. Pythonの実行環境を用意する
2. NixOSの設定項目とソフトウェアの一覧(約10MB)をダウンロードする
3. 検索用のデータベース(約37MB)を `~/.local/share/nixgen` に作る
4. 使い終わった元データを消す
5. ブラウザで <http://127.0.0.1:8823/> を開く

画面が3つに分かれていれば成功です。左が検索、真ん中が入力欄、右が出来上がっていくファイルです。検索欄に `openssh` と入れて、いちばん上の結果をクリックしてみてください。右側にファイルが1行増えれば、正しく動いています。

終わるときはターミナルで **Ctrl-C** を押します。2回目以降はデータベースが出来ているので、1秒ほどで立ち上がります。

**更新したはずなのに変わらないときは。** Nixは `github:` の指す先を**1時間ほど記憶します。** 更新直後に起動すると、前のバージョンが動くことがあります。取得し直すにはこうします。

```bash
nix run --refresh github:hatake716/nixgen
```

いまどちらが動いているかは、画面上部のビルド番号で分かります。

### ステップ3 — 毎回使うなら(任意)

`nixgen` と打つだけで起動できるようにしておけます。

```bash
nix profile install github:hatake716/nixgen
nixgen
```

**この方法で入れたものは固定されます。** 明示的に指示するまで更新されません。

```bash
nix profile upgrade nixgen
```

要らなくなったら `nix profile remove nixgen` で消せます。

### ステップ4 — 作ったファイルを使う

画面右上の **Download generated.nix** を押して、ファイルを保存します。保存先は、いま使っている `configuration.nix` と同じ場所です。たいていは `/etc/nixos/` です。

次に、`configuration.nix` を開いて、`imports` のリストに1行足します。

```nix
{
  imports = [
    ./hardware-configuration.nix
    ./generated.nix          # ← この行を足す
  ];
}
```

これで「`generated.nix` の中身も設定として読んでください」という意味になります。**元の `configuration.nix` の中身には一切触りません。**

適用する前に、問題がないか確認します。

```bash
sudo nixos-rebuild dry-build
```

エラーが出なければ、実際に適用します。

```bash
sudo nixos-rebuild switch
```

**元に戻したくなったら、足した1行を消してもう一度 `switch` するだけです。** 他の設定は何も変わっていないので、確実に元の状態に戻ります。

### うまくいかないとき

**`experimental Nix feature 'nix-command' is disabled`**
ステップ1をやっていないか、`nixos-rebuild switch` がまだ済んでいません。

**`does not contain a 'flake.nix', searching up`**
または **`Path 'build' does not exist in Git repository`**
gitで管理しているフォルダの中で実行しています。`/etc/nixos` がよくある例です。flakesは「gitに登録済みのファイル」しか見ないという仕様があり、登録していないファイルは存在しない扱いになります。上の `github:` の形で起動すれば回避できます。

**`Address already in use`**
8823番のポートを別のソフトが使っています。番号を変えてください。

```bash
nixgen --port 9000
```

**ブラウザが開かない**
<http://127.0.0.1:8823/> を自分で開いてください。ターミナルにも同じアドレスが出ています。

**最初からやり直したい**
データベースを消してから起動し直すと、作り直されます。

```bash
rm -rf ~/.local/share/nixgen
```

## 使い方

### 探す

24,517個を一覧から探すのは無理なので、**検索が入口になります。**

サービス名を打てば、たいてい目的の項目が先頭に出ます。`firewall` と入れれば `networking.firewall.enable` が、`ssh` と入れれば `services.openssh.enable` が上に来ます。

上のタブは左から **Setup**、**Options**(設定項目)、**Packages**(ソフトウェア)です。新しいマシンで使う順に並んでいます。**起動時はSetupが開きます。** 検索したいときは **Options** をクリックしてください。Packagesで選んだものは、インストールするソフトの一覧に追加されます。

*Hide options that need hand-written Nix* にチェックを入れると、**入力欄が用意されている項目だけ**に絞れます。全体の88.3%がこれに当たります。残りは自分でNixの文を書く必要がある項目で、慣れないうちは隠しておくほうが混乱しません。

パッケージ一覧は**アルファベット順**で出力されます。読み込み時も、追加したときも同じです。Nixは順序を気にしませんが、並んでいるほうが読みやすく、1つ足したときの差分も小さくなります。

### 既存の configuration.nix を読み込む

**Import configuration.nix** を押してファイルを選ぶと、いまの設定がフォームに展開されます。**選んだファイルは読むだけで、書き換えは一切しません。**

読み込んだ項目は、次の4つに分かれます。全部が出力に入るので、消えるものはありません。

| 分類 | 意味 |
|---|---|
| **フォームに反映** | 入力欄で編集できる形になったもの。ほとんどはここに入ります |
| **そのまま転記 — モジュール構造** | `imports` の行など。設定そのものではありませんが、消すと他のファイルが読み込まれなくなるので、そのまま写します |
| **そのまま転記 — 値が式** | `lib.mkIf ...` のように「条件によって変わる値」。フォームでは表現できないので、書かれていたとおりに写します |
| **そのまま転記 — この版に無い** | NixOSのバージョンが上がって、なくなったか名前が変わった項目 |

**そのまま転記された行は、色を変えて表示されます。** ファイルにも行末に `# verbatim` というメモが付くので、ダウンロードしたあとでも見分けられます。

とくに4つ目は要注意です。**存在しない項目が残っていると `nixos-rebuild` が拒否します。** 捨てずに目立たせているのは、それに気付いてもらうためです。

### 新規マシン用のスターターファイル

NixOSを入れたばかりで、まだ `flake.nix` が無い場合に使います。

**Setup** タブを開くと、必要な2つのファイルが出てきます。生成した設定を読み込む `configuration.nix` と、システムを組み立てる `flake.nix` です。右上のタブで切り替えて、それぞれダウンロードできます。

中身はすべて画面から変えられます。

| 項目 | 説明 |
|---|---|
| Host name | マシンの名前です |
| Main user | 普段使うアカウント名。チェックを外せば、ユーザーの設定ごと省けます |
| nixpkgs release | 最新の安定版か、その前2つ。`flake.nix` がこれを指します |
| Architecture | 普通のパソコンなら `x86_64-linux` です |
| Boot loader | UEFIの機械なら systemd-boot、古いBIOSの機械ならGRUB(ディスク名を聞かれます) |
| NetworkManager | ネットワーク接続の管理ソフト。外すと該当の行が消えます |
| Flakes | ステップ1で有効にしたあの機能です |
| Groups | ユーザーが入るグループ。`wheel` が `sudo` を使うための指定です |
| `system.stateVersion` | **最初に入れたNixOSのバージョン。新しい版に合わせて上げないでください** |

**チェックを外した項目は、コメントアウトではなく行ごと消えます。** 指定したものだけが残るので、ファイルが無駄に長くなりません。

### 同じ項目が2つのファイルに書かれた場合

スターターの `configuration.nix` と `generated.nix` が、同じ項目を設定してしまうことがあります。**その行は赤く表示され、入力欄にも「also in configuration.nix」という印が付きます。**

たいていは問題ありません。スターター側は `lib.mkDefault`(＝「他になければこれを使う」という指定)で書かれているので、`generated.nix` 側が優先されます。

問題になるのは、**両方が `lib.mkDefault` だったとき**です。優先順位が同じになり、NixOSはどちらを使うか決められません。

```
error: The option `networking.hostName' has conflicting definition values
```

このときは、どちらか片方のファイルから該当の行を消してください。

### Check syntax でできること・できないこと

画面右上の **Check syntax** は、**括弧の閉じ忘れやセミコロンの抜け**といった「Nixの文法として壊れている」箇所を見つけます。

ただし、**値の中身が正しいかどうかは見ていません。** 数字を入れるべきところに文字を入れていても、このチェックは通ります。

そこを確かめられるのは `sudo nixos-rebuild dry-build` だけです。**適用する前に必ず実行してください。**

### 日本語で読む

画面は普通のWebページなので、ブラウザの翻訳機能がそのまま使えます。Chromeなら右クリックから「日本語に翻訳」を選んでください。

**翻訳されるのは説明文だけです。** 項目名やソフトウェア名、出来上がったファイルの中身は英語のまま残ります。`services.openssh.enable` が翻訳されてしまうと、設定として成立しなくなるからです。

### 起動時のオプション

```bash
nixgen                       # nix run github:hatake716/nixgen でも同じ
nixgen --port 9000           # 使うポート番号を変える
nixgen --no-browser          # ブラウザを自動で開かない
```

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `NIXGEN_DATA` | `~/.local/share/nixgen` | データベースの置き場所 |
| `NIXGEN_CHANNEL` | `nixos-26.05` | どのバージョンの項目を扱うか |

リリースを切り替える簡単な方法は、Setupタブの **nixpkgs release** です。まだ作られていないリリースを選ぶと、インデックスの構築を提案します。初回のみ数分、以降の切り替えは瞬時です。リリースごとに別のデータベースを持つためで、**選択は再起動後も保持されます。**

`NIXGEN_CHANNEL` は、初回にどのリリースを作るかの指定として引き続き使えます。

```bash
rm -rf ~/.local/share/nixgen
NIXGEN_CHANNEL=nixos-25.11 nixgen
```

**いまは正式リリース版のみ対応しています。** 理由は「できないこと」に書きました。

### 別のパソコンから使う

この道具には**ログイン機能がありません。** 自分のパソコンからしか繋がらない設定(`127.0.0.1`)にしてあるので、そのままにしてください。

別のパソコンから使いたい場合は、SSHで通り道を作ります。

```bash
ssh -L 8823:127.0.0.1:8823 相手のマシン名
```

そのうえで、手元のパソコンで <http://127.0.0.1:8823/> を開きます。

## 仕組み(興味のある方向け)

ここから先は、使うだけなら読まなくて大丈夫です。

### 項目の一覧は自分で書いていません

NixOSは、全バージョンについて**全設定項目のデータを機械が読める形で公開しています。**

```
https://channels.nixos.org/nixos-26.05/options.json.br
https://channels.nixos.org/nixos-26.05/packages.json.br
```

項目名、型、初期値、説明文、どのファイルで定義されているか。公式ドキュメントもこのデータから作られています。nixgenが持っている一覧は、全部ここから来ています。**項目ごとの手書き定義は1つもありません。**

### 難しいのは「型」の扱い

厄介なのは、各項目の「型」が**プログラムが読む形式ではなく、人間向けの文章**で書かれていることです。しかも1,247通りあります。

```
"boolean"
"null or (list of string)"
"16 bit unsigned integer; between 0 and 65535 (both inclusive)"
"attribute set of (submodule)"
```

この文章を解釈して、「ON/OFFのスイッチ」「数値入力」「選択肢」などに振り分けています。**24,517項目のうち21,652項目(88.3%)に、専用の入力欄を用意できました。** 残りはNixの文を直接書く欄になります。

ただしその大半は、中に子項目を持つ「入れ物」の項目です。子のほうは個別に編集できるので、実際に手書きが必要な場面は12%より少なくなります。

### 検索の並び順

「クエリが項目名にどう一致したか」で大まかに分け、そのあと階層の浅さ、末尾が `.enable` かどうか、の順に並べています。

効いているのは**区切りごとの一致判定**です。`firewall` と入れたとき、`networking.firewall.enable` が先に来て `services.firewalld.enable` が後になるのは、前者では `firewall` がドットで区切られた1つの塊になっているからです。

### 壊れないことの確かめ方

出力したファイルが本当にNixとして正しいかを、**本物のNixのパーサに通して確認しています。** ランダムに選んだ8,000項目に、意地悪な値(引用符、バックスラッシュ、改行、空文字、日本語など)を入れて生成し、すべて通ることを確かめています。

この方法で、実際に3つのバグが見つかりました。

| バグ | 内容 |
|---|---|
| 名前を埋める場所の形が一様でない | `<name>` だけでなく `<n>` や `*` もある。5,080項目(21%)が該当 |
| `[ -1 ]` は文法エラー | リストの中の負の数には括弧が要る |
| `if` や `rec` は予約語 | 項目名に使うと引用符が必要 |

スターターファイルも同じ方針で、**実際のNixOSシステムとして最後まで組み立てられるか**を確認しています。

## できないこと

**開発版(unstable)への対応。** `nixos-unstable` も同じオプションデータを公開しているので、**不可能ではなく、単に未実装です。**

問題は時点のずれです。チャンネルは常に最新のスナップショットを返しますが、`flake.lock` は特定のコミットを固定します。unstableは毎日変わるため、**ビルド対象には存在しないオプションをフォームが提示してしまいます。** しかも `Check syntax` は通ってしまい、失敗が表面化するのは `nixos-rebuild` の段階です。原因が最も分かりにくい形です。

解決の道筋はあります。全チャンネルが `git-revision` を公開しているので、取り込んだスナップショットのコミットをflakeに固定すれば、ずれは構造的に消えます。それと「インデックスがどれくらい古いか」の表示。この2つが揃えば対応できます。まだ作っていません。

**チャンネルの混在は別の話で、こちらは対象外のままです。** パッケージはoverlayでunstableから持ってこられますが、オプションはできません(unstableの `services.foo.*` はunstableのモジュールセットを前提にするため)。カタログの半分は選べて半分は選べない、という道具は、対応しないより悪いと考えています。

**元のファイルへの書き戻し。** 読み込みはできますが、書き戻しはしません。既存の書き方やコメントを保ったまま値だけ差し替えるのは格段に難しく、失敗すると動いているシステムを壊します。**読むだけだから安全**、という設計です。

**値が正しいかの判定。** `nixos-rebuild dry-build` の仕事です。

**入れ物ごとの一括設定。** `services.nginx.virtualHosts.<name>.root` は設定できますが、`services.nginx.virtualHosts` をまとめて1つとしては扱えません。

## 開発

```bash
git clone https://github.com/hatake716/nixgen.git
cd nixgen
nix develop                                  # python3, brotli, curl, sqlite
./build/fetch-data.sh nixos-26.05
python3 build/build_index.py --channel nixos-26.05
python3 build/server.py
```

この手順だと、データベースがホームではなく `./data/` に作られ、編集中のファイルがそのまま動きます。cloneする場所は、既存のgitリポジトリの外にしてください(理由は「うまくいかないとき」と同じです)。

```
build/
  nixgen_core.py    型の文章を解釈して、Nixのコードを組み立てる部分(外部ライブラリなし)
  nix_import.py     既存の configuration.nix を読む部分
  starter.py        Setupタブの configuration.nix / flake.nix
  releases.py       存在するリリースの探索と、インデックスの構築
  build_index.py    公開データ -> SQLite + 全文検索
  server.py         標準ライブラリだけのHTTPサーバ
  fetch-data.sh     公開データのダウンロード
  static/           画面(素のJavaScript、ビルド工程なし)
tools/
  fuzz.py           レンダラの回帰テスト + ファジング
data/
  nixgen.sqlite     作られるデータベース。gitには入れません
docs/
  index.html        ホームページ。GitHub Pagesが /docs から配信します
  screenshot*.png
CHANGELOG.md        各バージョンの変更点。前半が英語、後半が日本語
CLAUDE.md           開発時の前提と、壊してはいけない不変条件
flake.nix
flake.lock          nixpkgsのバージョンを固定します
```

`docs/index.html` は単体で完結し、リンクはこのリポジトリを指しています。フォークする場合は中の `hatake716` を書き換え、**Settings → Pages** で `main` / `/docs` を指定してください。

## 更新履歴

動かしているバージョンは、アプリ画面上部のオプション数の右側に出ています。**直したはずの挙動が変わらないときは、まずこの番号を見てください。** 古いファイルが配信されている状態と、修正が効いていない状態は、見た目では区別が付きません。

古いものが出る原因は3つあります。ブラウザのキャッシュ(**Ctrl+Shift+R**)、Nixが `github:` の指す先を1時間記憶していること(`nix run --refresh …`)、`nix profile` で入れたものが固定されていること(`nix profile upgrade nixgen`)。

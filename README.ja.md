**インストール直後から、使えるマシンまで。オプション名を1つも知らないまま。** 設定項目24,557個とソフトウェア144,245個を検索し、型に応じたウィジェットで値を入れると、**マシンに何も起きないうちに中身を読める**設定ファイルが出てきます。

![nixgen](docs/screenshot.png)

### 3つの理由

**1. 初回ログインから使えるデスクトップ。** GNOME・KDE Plasma・Xfce・Cinnamon・COSMIC・LXQt・i3、そしてシェルが最初から載った状態で出てくる Wayland コンポジタ2つ、Sway + noctalia と niri + noctalia。デスクトップを有効にする1行は誰でも書けます。誰も教えてくれないのは**その周りの残り全部**です。グリーターとその Wayland モード、NixOS がビルド時に検証するセッション名、XWayland、シェルの自動起動ユニットと**アプリを起動できる PATH**、既定設定が名指しする端末、キーリング、放っておくと2つ出るバー。**どれも実機で動かして、実際に踏んで分かったもの**です。

**2. 日本語環境が、通しで整う。** ロケール、コンソールのキーマップ、そして X **と** Wayland **両方**のキーボードレイアウト。この2つは別の設定で、**Wayland 側はどこにも書かれていない環境変数**です。さらに fcitx5 と mozc、そして**実際に動くセッションに合わせたフロントエンド**。アプリ自身も全文を英日併記で表示し、オプション名は機械翻訳から守ります。訳された `services.openssh.enable` は Nix として無効だからです。

**3. あなたが実行するまで、マシンには何も起きない。** nixgen は**新しいファイルを作るだけ**で、あなたのファイルは書き換えません。読み込んだ `configuration.nix` は最後まで**読むだけ**です。特権の口は1つもありません。**このサーバーにシステムを変更する能力がない**のは、認証の無いローカルサーバーが、ブラウザで開いた任意のページから叩ける入口になるからです。代わりに**コマンドを1つ渡します**。中身を読んでから、`dry-build` で確かめてから切り替えられ、置き換えられたファイルは隣に残ります。

3つめがあるから、1つめと2つめを試せます。**綺麗に元へ戻せるデスクトップは、気軽に試せるデスクトップ**です。

English: [README.md](./README.md) ·
ホームページ: <https://hatake716.github.io/nixgen/>

> **ベータ版です。** 作者の自宅マシンと仮想マシンでは動いていますが、それ以外の環境で何が起きるかは分かっていません。適用する前に、後述の `dry-build` で必ず確認してください。

## この道具は何をするのか

NixOSでは、システムの設定を1つのファイルに書きます。SSHを有効にしたいなら、こう書きます。

```nix
services.openssh.enable = true;
```

問題は、**この「項目の名前」を覚えていないと何も書けない**ことです。項目は全部で24,557個あります。公式ドキュメントは英語で、目的の項目にたどり着くまでに時間がかかります。

nixgenは、この部分を肩代わりします。

1. 検索欄に `ssh` と入力する
2. 出てきた `services.openssh.enable` をクリックする
3. スイッチをONにする
4. 右側に `services.openssh.enable = true;` と書かれたファイルが出来上がる

項目名を覚えていなくても、思いついた単語で探せば見つかります。

### 誰に向いているか

- **設定項目の名前を覚えていられない人。** 使う頻度が低い設定ほど、毎回ドキュメントを探すことになります
- **NixOSを始めたばかりの人。** 「そもそも何を設定できるのか」が分からない段階では、検索欄に単語を入れて眺めるだけでも地図の代わりになります
- **バージョンを上げた直後の人。** 手元の設定ファイルを読み込ませると、**なくなった項目に色が付いて出てきます**

### 誰に向いていないか

- **項目名をだいたい覚えていて、エディタで直接書いたほうが速い人。** この道具は遠回りにしかなりません
- **NixOS以外のLinuxを使っている人。** 残念ながらNixOS専用です

## インストール

必要なのはNixOS、または他のLinux上のNixだけです。**ファイルをダウンロードする必要はありません。**

### ステップ1 — flakesを有効にする

「flakes」はNixの新しい書き方です。この道具はそれを使うので、先に有効にしておく必要があります。NixOSを新規インストールした直後は無効になっています。

まず、有効かどうかを確認します。

```bash
nix flake --help
```

**ヘルプがずらっと表示されたら、すでに有効です。** ステップ2へ進んでください。

「実験的機能です」というエラーが出た場合は、設定ファイル(`/etc/nixos/configuration.nix`)を開いて、`{` と `}` の間に次の1行を足します。

```nix
nix.settings.experimental-features = [ "nix-command" "flakes" ];
```

保存したら、システムに反映させます。

```bash
sudo nixos-rebuild switch
```

もう一度 `nix flake --help` を実行して、ヘルプが出れば成功です。

### ステップ2 — 起動する

```bash
nix run github:hatake716/nixgen
```

**これだけです。** ダウンロードもインストール作業も要りません。Nixが必要なものを勝手に集めて起動します。

**初回は5分ほどかかります。** 内部では次のことをしています。

1. Pythonの実行環境を用意する
2. NixOSの設定項目とソフトウェアの一覧(約10MB)をダウンロードする
3. 検索用のデータベース(約37MB)を `~/.local/share/nixgen` に作る
4. 使い終わった元データを消す
5. ブラウザで <http://127.0.0.1:8823/> を開く

画面が3つに分かれていれば成功です。左が検索、真ん中が入力欄、右が出来上がっていくファイルです。検索欄に `openssh` と入れて、いちばん上の結果をクリックしてみてください。右側にファイルが1行増えれば、正しく動いています。

終わるときはターミナルで **Ctrl-C** を押します。2回目以降はデータベースが出来ているので、1秒ほどで立ち上がります。

**更新したはずなのに変わらないときは。** Nixは `github:` の指す先を**1時間ほど記憶します。** 更新直後に起動すると、前のバージョンが動くことがあります。取得し直すにはこうします。

```bash
nix run --refresh github:hatake716/nixgen
```

いまどちらが動いているかは、画面上部のビルド番号で分かります。

### ステップ3 — ブラウザで設定を組み立てる

画面の中央に**5つの手順**が出ています。これがタブを使う順序です。初回の具体的な流れはこうなります。

1. **Setup** タブで、**Host name** にマシンの名前、**Main user** に自分のアカウント名を入れ、ブートローダーを選びます(UEFIのマシンなら **systemd-boot**、古いBIOSなら **GRUB**)。右側の `configuration.nix` と `flake.nix` が、入力に合わせて書き換わっていきます
2. **Options** タブで設定を足します。上部のプルダウンなら、大物(カーネル・シェル・デスクトップ・グラフィックス・言語・Flatpak)が一度に入ります。それ以外は検索です。`timeZone` と打ち、出てきた項目をクリックして、中央に現れた入力欄を埋めます
3. **Packages** タブでソフトウェアを足します。`firefox` を検索してクリックするか、**Common apps** の分野から選びます。クリックしたものは `environment.systemPackages` に入ります
4. 右上の **Check syntax** を押します。`構文に問題ありません。` と出れば合格です。指摘が出たら、先に進む前に直します
5. **Download all three** を押します。ホスト名の付いた書庫が1つ出てきます。中身は nixgen が書いた3つのファイルです

足したものはどれも、右側のファイルに**普通のテキストとして見えています**。隠れるものはなく、どのカードも後から変更・削除できます。各タブの詳しい説明は、後半の[使い方](#使い方)にあります。

### ステップ4 — マシンに載せる

**新しいマシンの場合**(インストーラが書いた設定のまま動いている場合)は、書庫を展開して3ファイルをコピーします。

```bash
cd ~/ダウンロード        # 書庫が保存された場所へ
tar -xzf desktop.tar.gz
sudo cp desktop/*.nix /etc/nixos/
```

(`desktop` の部分は、Host name に入れた名前になります。)もとの `configuration.nix` は上書きされます。ディスク構成を書いた `hardware-configuration.nix` は書庫に入っていないので、そのまま残ります。アプリの **System update** ボタンは、この一連の手順を**各段階の確認付き・バックアップ付き**で代行します。

確認してから、適用します。

```bash
sudo nixos-rebuild dry-build
sudo nixos-rebuild switch
```

最初の `switch` で flakes も有効になります。以降は、Setup タブに表示されているこのコマンドを使います。

```bash
sudo nixos-rebuild switch --flake /etc/nixos#desktop
```

**手書きの configuration.nix を使い続ける場合**は、`generated.nix` だけを受け取ります(**Download generated.nix** ボタン)。自分の `configuration.nix` の隣に置き、`imports` に1行足してください。

```nix
{
  imports = [
    ./hardware-configuration.nix
    ./generated.nix          # ← この行を足す
  ];
}
```

それ以外には何も触りません。**この1行を消して `switch` し直せば、すべて元に戻ります。**

### うまくいかないとき

**`experimental Nix feature 'nix-command' is disabled`**
ステップ1をやっていないか、`nixos-rebuild switch` がまだ済んでいません。

**`does not contain a 'flake.nix', searching up`**
または **`Path 'build' does not exist in Git repository`**
gitで管理しているフォルダの中で実行しています。`/etc/nixos` がよくある例です。flakesは「gitに登録済みのファイル」しか見ないという仕様があり、登録していないファイルは存在しない扱いになります。上の `github:` の形で起動すれば回避できます。

**`port 8823 is already in use`**
たいていの場合、**前に起動したnixgenがまだ動いています。** <http://127.0.0.1:8823/> を開いて、ヘッダーのビルド番号を確かめてください。思っていたバージョンと違えば、それが古いほうです。起動したターミナルで **Ctrl-C** を押せば終わります。

本当に別のソフトが使っているなら、番号を変えてください。

```bash
nixgen --port 9000
```

**ブラウザが開かない**
<http://127.0.0.1:8823/> を自分で開いてください。ターミナルにも同じアドレスが出ています。

**最初からやり直したい**
データベースを消してから起動し直すと、作り直されます。

```bash
rm -rf ~/.local/share/nixgen
```

**思ったよりディスクを使っている**
インデックスはチャンネルごとに1つ、約37MBです。再構築しても同じファイルを置き換えるだけなので、何度やっても増えません。増えるのは**これまでに選んだチャンネルの数だけ**です。

```
~/.local/share/nixgen/
├── nixgen.sqlite                  初回に作られるインデックス
├── nixgen-nixos-unstable.sqlite   チャンネルを切り替えるたびに1つ増えます
├── nixgen-nixos-25.11.sqlite      それぞれ約37MB
└── CURRENT                        前回選んだチャンネルの記録
```

チャンネルが一覧から外れると、そのインデックスはもう選べません。Setupタブに残っている容量が表示され、まとめて削除できます。

## 使い方

起動すると、画面中央に**5つの手順**が出ます。これがそのまま**進める順序**です。

1. **Setup** — マシンそのものと、2つのスターターファイル。すでに `configuration.nix` がある場合は、先に **Import configuration.nix** を押します
2. **Options** — 設定項目
3. **Packages** — ソフトウェア
4. **Check syntax** — 指摘が出たら直します
5. **Download all three** — 切り替える前に `sudo nixos-rebuild dry-build`

タブにはいつでも戻れます。この順序は**どこから始めるか**の話で、一度離れたら戻れないわけではありません。何か1つ設定を足すと、手順が出ていた場所は設定の一覧に変わります。

**インストールから切り替えまでの一本道は、上の[インストール](#インストール)の節がすでに通しで説明しています。** ここから先はリファレンスです。タブごと・ボタンごとの詳細と、その理由を書いています。

### Setup — 新規マシン用のスターターファイル

NixOSを入れたばかりで、まだ `flake.nix` が無い場合に使います。

**Setup** タブには、必要な2つのファイルが用意されています。生成した設定を読み込む `configuration.nix` と、システム全体を組み立てる `flake.nix` です。画面右上のファイルタブで切り替えて、それぞれダウンロードします。

**3つまとめて受け取ることもできます。** 画面右上の **Download all three** を押すと、`configuration.nix`・`flake.nix`・`generated.nix` を**ホスト名のディレクトリに入れた `.tar.gz`** が出てきます。ファイルタブの最後にある **all three** は、中身の説明を表示したうえで同じ書庫を渡します。

```bash
tar -xzf desktop.tar.gz
```

`.zip` ではなく `.tar.gz` なのは、**NixOS には `tar` と `gzip` が最初から入っていて、`unzip` は入っていない**ためです。`hardware-configuration.nix` は含まれません。これはそのマシンのディスク構成を書いたもので、あなたのものだからです。このタブで **Check syntax** を押すと、**3つとも**構文検査します。

4つのファイルが揃うと、こうなります。

```
/etc/nixos/
├── flake.nix                   Setupタブから。システム全体の入り口
├── configuration.nix           Setupタブから。手で書く側の設定
├── hardware-configuration.nix  インストール時に作られたもの。触りません
└── generated.nix               Options / Packages で作った設定
```

`flake.nix` が `configuration.nix` を読み、`configuration.nix` が残り2つを読みます。適用するコマンドは画面にも出ています。

```bash
sudo nixos-rebuild switch --flake /etc/nixos#ホスト名
```

中身はすべて画面から変えられます。

| 項目 | 説明 |
|---|---|
| Host name | マシンの名前です |
| Main user | 普段使うアカウント名。チェックを外せば、ユーザーの設定ごと省けます |
| nixpkgs channel | 最新の安定版、その前2つ、`nixos-unstable` のいずれか。**選んだチャンネルから、すべてが来ます** |
| What `flake.nix` points at | 既定は**ブランチ**で、更新が順に届きます。もう一方は**コミット**で、画面に出ていたオプションと、実際にビルドされるものが必ず一致します |
| Architecture | 普通のパソコンなら `x86_64-linux` です |
| Boot loader | UEFIの機械なら systemd-boot、古いBIOSの機械ならGRUB(ディスク名を聞かれます) |
| NetworkManager | ネットワーク接続の管理ソフト。外すと該当の行が消えます |
| Flakes | ステップ1で有効にしたあの機能です |
| Groups | ユーザーが入るグループ。`wheel` が `sudo` を使うための指定です |
| `system.stateVersion` | **最初に入れたNixOSのバージョン。新しい版に合わせて上げないでください** |

**チェックを外した項目は、コメントアウトではなく行ごと消えます。** 指定したものだけが残るので、ファイルが無駄に長くなりません。

### Setup — 既存の configuration.nix を読み込む

**Import configuration.nix** を押してファイルを選びます。**選んだファイルは読むだけで、書き換えは一切しません。**

**入る先は `configuration.nix` で、module ではありません。** あのファイルはこのマシン自身のもので、Setup タブが書くものだからです。

| 読み込んだファイルの内容 | 行き先 |
|---|---|
| ホスト名、ユーザーとグループ、アーキテクチャ、ブートローダー、NetworkManager、flakes、`system.stateVersion` | **Setup** タブの入力欄。そこから該当行が書き出されます |
| `imports` | nixgen が書く `configuration.nix` の imports に統合されます |
| それ以外すべて | 同じファイルに、どこから来たかのコメントを付けて**そのまま**写します |

module(`generated.nix`)には触れません。あちらは、**Options** と **Packages** で後から足すもののための場所です。読み込んだファイルにあった項目を Options で足すと、その行は赤くなり、ステータス欄がどれかを伝えます(Setup タブが書く項目と同じ警告です)。

**前回作った `generated.nix` は、逆向きに戻せます。** **Import generated.nix** を押すと、中身が module のカードになります。もともとそこから出てきたものだからです。「タブを閉じると入力内容は消える」の往復は、この2つで完結します。`generated.nix` をダウンロードしておき、あとで読み戻してください。

### 同じ項目が2つのファイルに書かれた場合

スターターの `configuration.nix` と `generated.nix` が、同じ項目を設定してしまうことがあります。**その行は赤く表示され、入力欄にも「also in configuration.nix」という印が付きます。**

たいていは問題ありません。スターター側は `lib.mkDefault`(＝「他になければこれを使う」という指定)で書かれているので、`generated.nix` 側が優先されます。

問題になるのは、**両方が `lib.mkDefault` だったとき**です。優先順位が同じになり、NixOSはどちらを使うか決められません。

```
error: The option `networking.hostName' has conflicting definition values
```

このときは、どちらか片方のファイルから該当の行を消してください。

### Options — 探す

24,557個を一覧から探すのは無理なので、**検索が入口になります。**

サービス名を打てば、たいてい目的の項目が先頭に出ます。`firewall` と入れれば `networking.firewall.enable` が、`ssh` と入れれば `services.openssh.enable` が上に来ます。

タブは左から **Setup**、**Options**(設定項目)、**Packages**(ソフトウェア)の順です。新しいマシンで使う順番に並べてあります。**起動時に開くのはSetupです。** 設定を探すときは **Options** に切り替えてください。Packagesで選んだものは `environment.systemPackages` に足されます。

### Options — カーネルを選ぶ

**Options** タブには **Kernel** のプルダウンもあります。標準・最新・LTS・Zen から選べます。設定するのは `boot.kernelPackages` で、これは値が Nix の式である raw なオプションです。フォームで保持できる型ではないため、**式そのもの**が編集可能な入力欄として module に入ります。

書き込む前に、いずれの名前もパッケージ索引で確認します。ステータス欄には見つかったバージョンが出るので、LTS を選ぶと `linux 6.12.102` のように**どの系列なのかが分かります**。なお nixpkgs に `linuxPackages_lts` はありません。LTS は新しい順に並べた系列の一覧で、**そのチャンネルが今も持っている最初のもの**が採用されます。

標準は、この設定を書かなかった場合と同じものです。**最新と Zen は動きます。** カーネル外のモジュールは動いているカーネルに合わせてビルドする必要があり、**NVIDIA のドライバは新しいリリースから数週間遅れる**のが通例です。切り替える前に `nixos-rebuild dry-build` で確かめてください。

### Options — シェルを選ぶ

**Kernel** と **Desktop** の間に **Shell** のプルダウンがあります。bash・zsh・fish から選べます。

**2項目です。忘れられがちなのは module のほう**です。`users.defaultUserShell` だけを設定すると、そのシェルは **`/etc/shells` に載らず、補完も入りません。** ログインはできますが、まともに動かない部分が残ります。それを登録するのが `programs.zsh.enable` と `programs.fish.enable` なので、一緒に入れます。これは**両方を評価して確認**しました。module を入れると `environment.shells` に `zsh` や `fish` が現れ、入れないと bash と sh だけのままです。

bash には `pkgs.bash` ではなく **`pkgs.bashInteractive`** を指定します。前者は readline 無しのビルドで、ログインシェルには向きません。

`users.defaultUserShell` は**このマシンの通常アカウント全部**に効きます。1人だけ変えたい場合は、`users.users.<name>.shell` を検索してください。

### Options — デスクトップ環境を選ぶ

**Options** タブに **Desktop** のプルダウンがあります。GNOME、KDE Plasma、Xfce、Cinnamon、COSMIC、LXQt、Sway + noctalia、niri + noctalia、i3 から選ぶと、NixOSマニュアルが挙げている項目が追加されます。追加されるのは**通常のオプションと同じ**なので、あとから変更も削除もできます。

**Hyprland は以前は選べましたが、いまは非表示です。** キーボード配列も端末も警告バナーも、Hyprland がホームに書き出す自前の設定ファイルが握っていて、**nixgen が書く設定を上書きします**。このフォームだけでは「動くデスクトップ」を約束できないためです。Hyprland を含むファイルの取り込みは今までどおり動き、デスクトップを切り替えたときの掃除も従来どおり働きます。

**すべてが同じ形ではありません。違いは意図的なものです。**

| | 追加される内容 |
|---|---|
| GNOME・Plasma・Xfce・Cinnamon・LXQt | Xサーバー、ログイン画面、デスクトップ本体 |
| i3 | Xサーバー、ログイン画面、ウィンドウマネージャ |
| COSMIC | 自前のログイン画面とデスクトップ本体。Wayland なので `services.xserver.enable` に相当するものがありません |
| Sway・niri | 1項目ずつ |

**Sway・niri を選ぶと gnome-keyring も設定されます。** コンポジタには secret service が無いので、ブラウザなど資格情報を保存するアプリはそのままでは動きません。また、**誰も開かないキーリングはログインのたびに2つめのパスワードを尋ねてきます**。デーモンは `services.gnome.gnome-keyring.enable` で入り、アンロックは `security.pam.services.login.enableGnomeKeyring` で行います。**sddm ではなく login サービス側**です — sddm の PAM スタックは `include login` の1行だけで、sddm 側のスイッチは何も変えないことを、生成された実ファイルを読んで確認しました。GNOME や Plasma に切り替えるとこの2つは外れます。あちらは自前で配線しているためです。

**Sway・niri を選ぶと `noctalia-shell` も一緒に入ります。** コンポジタはコンポジタそのものだけで、**パネルもランチャーも通知もありません。** noctalia はその上に載せる部分です。これは設定ではなく**パッケージ**なので(オプションのカタログには何もありません)、`environment.systemPackages` に**普通の1行として**入ります。入ったことはステータス欄にも出ますし、不要なら消せます。

**デスクトップを切り替えると、ディスプレイマネージャも入れ替わります。** NixOS は DM の2つ同時を受け付けません — gdm のモジュールが他を強制無効化するため、**前のデスクトップの lightdm が残っているとビルドエラー**になります(まさにその状態を評価して確認しました)。新しいデスクトップを選ぶと、それ以外のグリーターは module から外れ(sddm は Wayland スイッチも道連れ)、何を外したかはステータス欄に出ます。**デスクトップ本体は両方残ります。** 1つのログイン画面に2つのセッションは正当で、その状態を評価するとセッション一覧に両方が並ぶことも確認済みです。

**ログイン画面では、選んだデスクトップが最初から選択されています。** 各プリセットは `services.displayManager.defaultSession` も設定します(`gnome`、`xfce`、i3 は `none+i3` など)。この名前は推測ではなく、**評価済みシステムのセッション一覧から読み出しました**。NixOS はビルド時に実在するセッション名かを検査するからです。例外は COSMIC です。このオプションが効くのは GDM・LightDM・SDDM だけで、COSMIC 自前のログイン画面は唯一のセッションを最初から表示します。

**XWayland も有効にします。** X11 のアプリが動くようにするためです。Sway にはそのためのオプションがあり(既定値も有効です)、**どちらに設定されているかがカードで分かるよう明示**しています。**niri にはこのオプションがありません。** XWayland を内蔵していないためで、代わりに `xwayland-satellite` をパッケージとして入れます。**X11 のアプリから見えるようにするには、niri の設定ファイルからこれを起動してください。**

**sway 自身のバーは取り除きます。** `/etc/sway/config` の末尾には swaybar を時計付きで起動する `bar { }` ブロックがあり、noctalia を重ねると**画面にバーが2つ**出ます。これを消すオプションは無い(sway のモジュールに `extraConfig` はありません)ので、プリセットがこのファイルを**モジュール自身のものからその13行だけを除いたもの**に差し替えます。キー割り当ては全て残り、いちばん重要な2行も残ります。壁紙と、noctalia の起動元になるセッション連携を読み込む `include /etc/sway/config.d/*` です。この2行のために、元にするのは `pkgs.sway` ではなく **`config.programs.sway.package`** です。両者は同じバージョンの**別ビルド**で、素の `pkgs.sway` はどちらの行も無いようにパッチされています。生成結果を2つの nixpkgs リビジョンでビルドして確認しました。この差し替えは属性セットのブロックではなく**フラットな1行**(`environment.etc."sway/config".source = …`)で書きます。ファイルを読み戻すと属性セットは平坦化されるため、ブロックと平坦化された写しが並ぶと `attribute … already defined` でビルドが失敗するからです。

**キーボード配列は、Wayland でも言語に追従します。** `services.xserver.xkb` は wlroots 系コンポジタに届きません — 日本語設定のマシンが sway に US 配列でログインする、という形で発覚しました。これらのキーマップは libxkbcommon が作り、レイアウト未指定時のフォールバックは環境変数 `XKB_DEFAULT_LAYOUT` です。そこで言語プリセットが `environment.sessionVariables` 経由でこれを設定します。PAM がログイン時に適用するので、セッションの起動経路によらず届きます。**例外は Hyprland** です。自動生成される設定が `kb_layout = us` を明記しており、設定の行は環境変数に勝つので、そちらのファイルで変更してください。

**noctalia-shell はセッションと一緒に起動します。** コンポジタはパネルもランチャーも持たないのでプリセットが1つ入れますが、**誰も起動しないシェルはストアに置かれているだけ**なので、`graphical-session.target` に紐づけた user service も一緒に書きます。どちらもこの target に到達します。sway は既定設定が `sway-session.target` を起動し、その target がこれに `bindsTo` しています。niri は自前の systemd ユニットを同梱しています。このユニットは **PATH を自分で書きます。** NixOS の user service には `PATH=coreutils:findutils:…` だけが与えられるため、シェルは立ち上がっても**一覧に出したアプリを起動できません**。3つのコンポジタは user manager に入れる内容が揃っていないので、継承ではなく明示しています。

**niri には端末も入れます。** 端末を1つも持たず、既定のキー割り当てで開く先が無いためです。既定設定で動く `foot` を入れます。sway は foot と wmenu を、i3 は xterm と dmenu を既に持っています。

3つともログイン画面を持たないので、**sddm を Wayland モードで一緒に入れます。** 起動するとログイン画面が出て、セッション一覧にそのコンポジタが並びます。効いているのは `services.displayManager.sddm.wayland.enable` のほうです。**両方の設定ファイルをビルドして比べました。** 有効なら sddm の設定は `DisplayServer=wayland` になり、ログイン画面は weston の上で動きます。無効だと `DisplayServer=x11` で、**他に何もXを使わないマシンの前にX11のログイン画面だけが立つ**ことになります。テキストコンソールから起動する場合や `greetd` を使う場合は、この2枚のカードを削除してください。

i3 は**何も無い画面で起動**し、初回に設定ファイルを作るか尋ねてきます。タイル型の使い勝手をどうするかは、ここでは一切決めていません。

この機能がある理由は、項目名そのものです。`gdm` と `sddm` は `services.xserver` の外に移りましたが、**`lightdm` は移っていません。** `gnome` と `plasma6` は外に出ましたが、**`xfce` は中に残っています**(`cinnamon` も同様です)。`plasma5` は消えました。nixgenは**いま選んでいるチャンネルのカタログを1つずつ照合**するので、かつての名前ではなく実在する名前が入ります。

*Hide options that need hand-written Nix* にチェックを入れると、**入力欄が用意されている項目だけ**に絞れます。全体の88.3%がこれに当たります。残りは自分でNixの文を書く必要がある項目で、慣れないうちは隠しておくほうが混乱しません。

パッケージ一覧は**アルファベット順**で出力されます。読み込み時も、追加したときも同じです。Nixは順序を気にしませんが、並んでいるほうが読みやすく、1つ足したときの差分も小さくなります。

### Options — グラフィックドライバを選ぶ

**Options** タブには **Graphics** のプルダウンもあります。AMD・Intel・NVIDIA から選べます。どれを選んでも `hardware.graphics` と32bit側を有効にします。後者は **Steam や wine に必要**なものです。そのうえで、**そのカードに実際に必要なことだけ**を行います。

Intel には VAAPI ドライバも入ります。これが無いと動画のハードウェアデコードが働きません。AMD はこれ以上足しません。mesa が持っているからです。NVIDIA はXのドライバ名を指定し、modesetting を有効にし、`hardware.nvidia.open = false`(プロプライエタリのカーネルモジュール)を設定します。**このドライバが対応する全カードで動く選択**です。

`services.xserver.videoDrivers` を設定するのは NVIDIA だけです。既定は `modesetting` で、現行カーネルの AMD と Intel ではそれが正解だからです。

**NVIDIA のドライバは unfree なので、選ぶと `nixpkgs.config.allowUnfree = true;` も一緒に入ります。** この行が無いとビルドはファイルを拒否します。AMD や Intel に切り替えると NVIDIA のカード一式は外れますが、`allowUnfree` のカードは**他に必要とするものが無いときだけ**外れます。vscode や Steam なども unfree なので、パッケージ一覧にあればカードは残り、どれが理由かをステータス欄が名指しします。

### Options — 言語を選ぶ

**Options** タブの **Language** のプルダウンでは、英語・日本語・フランス語・ドイツ語・スペイン語・韓国語・中国語から選べます。**選ぶだけで言語設定が完結します。** ロケール、コンソールのキーマップ、Xのキーボードレイアウトが入ります。日本語・韓国語・中国語では、**fcitx5 と対応する入力エンジン**も設定されます。この3言語は入力メソッド無しには打てないためです。

**入力メソッドが有効なのに何も選ばれていないときは、fcitx5 を入れます。** その状態は警告して放置すべきものではなく、**それ自体がクラッシュ**だからです。`type` が無いとモジュールが `environment.systemPackages` に null のパッケージを入れ、`nixos-rebuild` は原因とは無関係な systemd を指して落ちます。**埋めるのは空欄のときだけ**で、`type` に ibus などが入っていればそれはあなたの選択なので触れません。埋めた場合はステータス欄でお知らせします。

**入力メソッドはセッションに追従します。** fcitx5 には2つのフロントエンドがあり、間違ったほうは中途半端に動きます(Wayland セッションで X11 側を使うと、ネイティブなアプリの入力が乱れます)。module にデスクトップが入っていれば、CJK の言語は `i18n.inputMethod.fcitx5.waylandFrontend` を**そのセッションに合わせて**設定します。後から別のデスクトップを選べば切り替わります。両方向を評価して確認済みで、有効時は `GTK_IM_MODULE`・`QT_IM_MODULE` が外れ、アプリは Wayland の text-input プロトコルを使います。

**あえてやっていないことが2つあります。** ひとつはフォントです。GNOME・Plasma・Xfce はいずれもCJKフォントと絵文字フォントを既に持っているので、足すものがありません。もうひとつは**タイムゾーン**です。**言語は場所ではない**ので、日本語だから `Asia/Tokyo`、とは決めつけません。**Options** で `timeZone` を検索して、ご自分で設定してください。

### Options — 地域を選ぶ

**Language** の下に **Region** の行があります。**分けてあるのは意図的**です。言語は場所ではないからです。選ぶと `time.timeZone` が設定されます。NixOS のこの設定は元々 `Region/City` の形なので、**1つの設定で地域と時刻の両方が決まります**。18か所を用意し、**どの名前も zoneinfo データベースと突き合わせて確認**しました。綴りが違ってもフォームは受け取ってしまい、あとから「静かに時計がずれている」という形でしか現れないためです。ここに無い場所は、**Options** で `timeZone` を検索して入力してください。

### Options — Flatpak を有効にする

**Options** タブのいちばん下の行にはプルダウンがありません。**Flatpak は有効か無効かのどちらか**で、選ぶものが無いからです。**Add** を押すと3つの設定が入ります。`services.flatpak.enable`、`xdg.portal.enable`、そして `xdg.portal.extraPortals` の `xdg-desktop-portal-gtk` です。

**portal は付け足しの配管ではありません。** Flatpak のアプリは、**xdg portal を通してシステムの外とやり取りします。** これが無いと、**ファイル選択ダイアログも画面共有も出ません。** GNOME と Plasma は自前のバックエンドを持っているので、その環境では GTK 版は予備です。不要ならそのカードを削除してください。

**設定ファイルでは代われない手順が1つあります。** インストール直後は**リモートが1つも登録されていない**ので、`flatpak install` は何も見つけられません。rebuild のあとに、flathub を一度だけ追加してください。

```bash
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
```

nixgen は Add を押したときにステータス欄でこれを案内します。**誰もが必ず引っかかる**うえに、**設定ファイルでは肩代わりできない**手順だからです。

### Packages — よく使うアプリから選ぶ

**Packages** タブに **Common apps** のプルダウンがあります。カテゴリを選ぶと結果一覧にアプリが並ぶので、**検索結果と同じようにクリックして追加します。** 勝手に入るものはありません。

12分野あり、**プルダウンには英語と日本語の両方が出ます。**

```
Web browsers — ブラウザ          Chat and sync — チャット・同期
Mail — メーラー                  Accessories — アクセサリー
Office — オフィスソフト          File managers — ファイラー
Audio and video — マルチメディア  Terminals — ターミナル
Graphics — グラフィックス        System tools — システムツール
Games — ゲーム                   Development — 開発
```

ここだけ日本語を併記しているのは、**分野名は機械翻訳が最も苦手とするもの**だからです。「Audio and video」は 音楽と動画 と訳されますが、この分野に入っているのは audacity や pavucontrol で、音楽の話ではありません。ブラウザの翻訳機能に書き換えられないよう固定してあります。

**絞った一覧であって、カタログではありません。** この道具の中で唯一、他人の好みで見えるものが決まる場所なので、小さく保っています。それ以外は検索欄で探してください。

**各パッケージにはアイコンが付きます。** 取得元は、**そのマシンに既に入っているアイコンテーマ**です(`/run/current-system/sw/share/icons`、ユーザープロファイル、`XDG_DATA_DIRS` の指す先)。**何もダウンロードしませんし、nixgenの依存も増えません。** その代わり、**いくつ表示されるかは何が入っているかで変わります。** テーマの揃ったデスクトップならほとんど出ますし、素のインストールならわずかです。アイコンが無いものは、**名前ごとに決まる色の上に頭文字**を表示します。`tmux` や `gcc` には、そもそもどこにもアイコンがありません。

5つのデスクトップ(GNOME・Plasma・Xfce・Cinnamon・COSMIC)の標準アプリも入っています。**二重に入れるためではありません**(デスクトップを有効にすれば標準アプリは既に入ります)。**そのデスクトップを使わずにアプリだけ取れるようにするため**です。Xfce で `gwenview`、GNOME で `cosmic-term`、Plasma で `gnome-calculator` を使いたい、といった場合です。

入れていないものも、同じ線引きによります。`cosmic-settings` や mint のテーマ類は、**そのデスクトップが動いていなければ意味がない**ので出していません。

名前は**いま選んでいるチャンネルのカタログで1つずつ照合**します。形式的な作業ではありません。`kdenlive` の実体は `kdePackages.kdenlive`、`0ad` は `zeroad`、`superTuxKart` は 25.11 と 26.05 の間に `supertuxkart` へ改名されています。**そのチャンネルに無いものは一覧に出ません。**

Steam はゲームの一覧に入っています。選ぶとステータス欄に案内が出ます。**パッケージとしても動きますが、`programs.steam.enable`(Options タブ)のほうが本筋です。** 32bit のグラフィックドライバを揃えるのはこちらで、リモートプレイのポート開放もできます。

### Check syntax — できること・できないこと

画面右上の **Check syntax** は、**括弧の閉じ忘れやセミコロンの抜け**といった「Nixの文法として壊れている」箇所を見つけます。

ただし、**値の中身が正しいかどうかは見ていません。** 数字を入れるべきところに文字を入れていても、このチェックは通ります。

そこを確かめられるのは `sudo nixos-rebuild dry-build` だけです。**適用する前に必ず実行してください。**

### Download all three — 最後の手順

**Check syntax** で問題が出なくなったら、**Download all three** を押します。書庫を `/etc/nixos` に展開し、既にある `hardware-configuration.nix` の隣に置いてください。書庫の中身については、上の [Setup の節](#setup--新規マシン用のスターターファイル)に書いてあります。

```bash
sudo nixos-rebuild dry-build
```

**問題が無いときだけ切り替えます。** `configuration.nix` と `flake.nix` は自分のものを使っていて `generated.nix` だけ欲しい場合は、そのファイルタブから受け取り、上の[ステップ4](#ステップ4--マシンに載せる)のとおり `imports` に `./generated.nix` を足してください。

### System update — このマシンに適用する

ヘッダーの右端にあるボタンで、**マシンそのものを変える唯一のボタン**です。

押すと、各段階の前に**3回**確認します。

1. **ブラウザ** — これから何が起きるかを示し、そのうえで書庫をダウンロードします
2. **ターミナル** — コマンドが書庫を展開して3ファイルを一覧表示し、`/etc/nixos` へコピーする前に確認します
3. **ターミナル** — `nixos-rebuild switch` の前に、もう一度確認します

2つめのダイアログが**コマンドを1つ渡し、クリップボードにコピー**します。ダウンロード先のフォルダ名が `Downloads` でも `ダウンロード` でも見つけます(まず `xdg-user-dir` に尋ね、その後どちらの名前も試します)。**bash・zsh・fish のいずれから貼っても動く**ことを確認済みです。あるシェルでそのまま動くシェル片が、別のシェルでも動くとは限らないためです。

**置き換えられたファイルは残ります。** `configuration.nix.~1~` のような名前で新しいものの隣に置かれるので、**やり直したくなったら戻せます。** **`hardware-configuration.nix` には一切触れません。** 書庫にも入っておらず、コマンドも名前を出しません。

**先に設定を終えてください。** **このマシンが起動に使う設定を置き換えます。** 必要な設定とソフトウェアを入れ、**Check syntax** を通してから使ってください。

**権限の要る部分を nixgen 自身が行わないのは意図的です。** このサーバーには認証がなく、`/etc/nixos` を上書きして再構築できる口を開けると、**同じブラウザで開いている任意のページから叩ける**ことになります。コマンドを渡す形にすることで、`sudo` と判断を本来あるべき場所に残しています。

### 日本語で読む

画面は普通のWebページなので、ブラウザの翻訳機能がそのまま使えます。Chromeなら右クリックから「日本語に翻訳」を選んでください。

**翻訳されるのは説明文だけです。** 項目名やソフトウェア名、出来上がったファイルの中身は英語のまま残ります。`services.openssh.enable` が翻訳されてしまうと、設定として成立しなくなるからです。

### 起動時のオプション

```bash
nixgen                       # nix run github:hatake716/nixgen でも同じ
nixgen --port 9000           # 使うポート番号を変える
nixgen --no-browser          # ブラウザを自動で開かない
```

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `NIXGEN_DATA` | `~/.local/share/nixgen` | データベースの置き場所 |
| `NIXGEN_CHANNEL` | `nixos-26.05` | どのチャンネルの項目を扱うか |

チャンネルを切り替える簡単な方法は、Setupタブの **nixpkgs channel** です。最新の安定版とその前2つ、それに `nixos-unstable` が並びます。まだ作られていないものを選ぶと、インデックスの構築を提案します。初回のみ数分、以降の切り替えは瞬時です。チャンネルごとに別のデータベースを持つためで、**選択は再起動後も保持されます。**

`NIXGEN_CHANNEL` は、初回にどのチャンネルを作るかの指定として引き続き使えます。

```bash
rm -rf ~/.local/share/nixgen
NIXGEN_CHANNEL=nixos-unstable nixgen
```

### unstableで使う

`nixos-unstable` も、番号付きリリースと並んで選べます。選ぶと**すべてがunstableになります。** オプションも、パッケージも、`flake.nix` も、`system.stateVersion` もです。unstableは名前にバージョンを含まないので、`stateVersion` だけはカタログから読み取ります(現時点では26.11)。

注意する点は**オプション一覧の鮮度**、ひとつだけです。unstableは翌日には別のツリーになっています。そこで、一覧がいつ公開されたものかをSetupタブに表示し、1日過ぎたら再構築を提案するようにしました。**この表示が無かったことが、unstableを長く非対応にしていた理由です。** いまはどのチャンネルでも表示します。

ずれを完全に避けたいなら、*What `flake.nix` points at* を**コミット**にしてください。画面に出ていたオプションと、ビルドされるツリーが同じものになります。ファイルを作り直すまで動きません(`nix flake update` でも動きません)。

### 別のパソコンから使う

この道具には**ログイン機能がありません。** 自分のパソコンからしか繋がらない設定(`127.0.0.1`)にしてあるので、そのままにしてください。

別のパソコンから使いたい場合は、SSHで通り道を作ります。

```bash
ssh -L 8823:127.0.0.1:8823 相手のマシン名
```

そのうえで、手元のパソコンで <http://127.0.0.1:8823/> を開きます。

## 仕組み(興味のある方向け)

ここから先は、使うだけなら読まなくて大丈夫です。

### 項目の一覧は自分で書いていません

NixOSは、全バージョンについて**全設定項目のデータを機械が読める形で公開しています。**

```
https://channels.nixos.org/nixos-26.05/options.json.br
https://channels.nixos.org/nixos-26.05/packages.json.br
```

項目名、型、初期値、説明文、どのファイルで定義されているか。公式ドキュメントもこのデータから作られています。nixgenが持っている一覧は、全部ここから来ています。**項目ごとの手書き定義は1つもありません。**

### 難しいのは「型」の扱い

厄介なのは、各項目の「型」が**プログラムが読む形式ではなく、人間向けの文章**で書かれていることです。しかも1,252通りあります。

```
"boolean"
"null or (list of string)"
"16 bit unsigned integer; between 0 and 65535 (both inclusive)"
"attribute set of (submodule)"
```

この文章を解釈して、「ON/OFFのスイッチ」「数値入力」「選択肢」などに振り分けています。**24,557項目のうち21,681項目(88.3%)に、専用の入力欄を用意できました。** 残りはNixの文を直接書く欄になります。

ただしその大半は、中に子項目を持つ「入れ物」の項目です。子のほうは個別に編集できるので、実際に手書きが必要な場面は12%より少なくなります。

### 検索の並び順

「クエリが項目名にどう一致したか」で大まかに分け、そのあと階層の浅さ、末尾が `.enable` かどうか、の順に並べています。

効いているのは**区切りごとの一致判定**です。`firewall` と入れたとき、`networking.firewall.enable` が先に来て `services.firewalld.enable` が後になるのは、前者では `firewall` がドットで区切られた1つの塊になっているからです。

### 壊れないことの確かめ方

出力したファイルが本当にNixとして正しいかを、**本物のNixのパーサに通して確認しています。** ランダムに選んだ8,000項目に、意地悪な値(引用符、バックスラッシュ、改行、空文字、日本語など)を入れて生成し、すべて通ることを確かめています。

この方法で、実際に3つのバグが見つかりました。

| バグ | 内容 |
|---|---|
| 名前を埋める場所の形が一様でない | `<name>` だけでなく `<n>` や `*` もある。5,082項目(21%)が該当 |
| `[ -1 ]` は文法エラー | リストの中の負の数には括弧が要る |
| `if` や `rec` は予約語 | 項目名に使うと引用符が必要 |

スターターファイルも同じ方針で、**実際のNixOSシステムとして最後まで組み立てられるか**を確認しています。

## できないこと

**チャンネルの混在。** 「オプションは安定版から、パッケージだけunstableから」という使い方はできません。今後対応する予定もありません。

パッケージだけならoverlayで持ってこられますが、オプションはそうはいきません。unstableの `services.foo.*` は、unstable側のモジュールがあって初めて成り立つからです。**カタログの半分は選べて半分は選べない道具**になるくらいなら、対応しないほうがましだと考えています。

**元のファイルへの書き戻し。** 読み込みはできますが、書き戻しはしません。書き方やコメントを保ったまま値だけ差し替えるのは桁違いに難しく、失敗したときに壊れるのは動いているシステムです。**読むだけなので危険がない**、という設計にしてあります。

**値が正しいかの判定。** `nixos-rebuild dry-build` の仕事です。

**入れ物ごとの一括設定。** `services.nginx.virtualHosts.<name>.root` は設定できますが、`services.nginx.virtualHosts` をまとめて1つとしては扱えません。

## 開発

```bash
git clone https://github.com/hatake716/nixgen.git
cd nixgen
nix develop                                  # python3, brotli, curl, sqlite
./build/fetch-data.sh nixos-26.05
python3 build/build_index.py --channel nixos-26.05
python3 build/server.py
```

この手順だと、データベースがホームではなく `./data/` に作られ、編集中のファイルがそのまま動きます。cloneする場所は、既存のgitリポジトリの外にしてください(理由は「うまくいかないとき」と同じです)。

```
build/
  nixgen_core.py    型の文章を解釈して、Nixのコードを組み立てる部分(外部ライブラリなし)
  nix_import.py     既存の configuration.nix を読む部分
  starter.py        Setupタブの configuration.nix / flake.nix
  releases.py       存在するリリースとそのコミットの探索、インデックスの構築
  build_index.py    公開データ -> SQLite + 全文検索
  server.py         標準ライブラリだけのHTTPサーバ
  fetch-data.sh     公開データのダウンロード
  static/           画面(素のJavaScript、ビルド工程なし)
tools/
  fuzz.py           レンダラの回帰テスト + ファジング
  import_check.py   読み込み側の回帰テスト。2つのリーダー両方を通します
  shots.py          実際のアプリを操作してスクリーンショットを撮り直します
data/
  nixgen.sqlite     作られるデータベース。gitには入れません
docs/
  index.html        ホームページ。GitHub Pagesが /docs から配信します
  screenshot*.png
.github/workflows/
  checks.yml        push のたびに両方のハーネスを走らせます
CHANGELOG.md        各バージョンの変更点。前半が英語、後半が日本語
CLAUDE.md           開発時の前提と、壊してはいけない不変条件
flake.nix
flake.lock          nixpkgsのバージョンを固定します
```

`docs/index.html` は単体で完結し、リンクはこのリポジトリを指しています。フォークする場合は中の `hatake716` を書き換え、**Settings → Pages** で `main` / `/docs` を指定してください。

## 更新履歴

[CHANGELOG.md](CHANGELOG.md#日本語) を参照してください。前半が英語、後半が日本語です。

動かしているバージョンは、アプリ画面上部のオプション数の右側に出ています。**直したはずの挙動が変わらないときは、まずこの番号を見てください。** 古いファイルが配信されている状態と、修正が効いていない状態は、見た目では区別が付きません。
